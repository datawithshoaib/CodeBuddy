# Deploying CodeBuddy to Vercel 🚀

This guide explains how to deploy **CodeBuddy** to Vercel.

---

## 🧭 Architecture Overview

CodeBuddy consists of two components:
1. **Frontend**: Next.js 16 (React 19 + Tailwind CSS + Lucide Icons) located in the [`frontend/`](frontend) directory.
2. **Backend**: FastAPI + LangGraph multi-agent system located in [`api/`](api) and [`agent/`](agent).

Because the agent performs long-running streaming operations, writes project files, and executes shell commands, the **recommended production architecture** is:
- **Frontend**: Deployed to **Vercel** (ultra-fast CDN, edge routing, zero-config SSR).
- **Backend**: Deployed to a container or cloud service with persistent execution (**Render**, **Railway**, or **Fly.io**).

---

## ⚡ Option 1: Recommended Setup (Vercel Frontend + Render/Railway Backend)

### Step 1: Deploy the FastAPI Backend (Render or Railway)

#### Deploy to Render:
1. Push your repository to GitHub.
2. Go to [Render Dashboard](https://dashboard.render.com/) and click **New +** → **Blueprint** (or **Web Service**).
3. Connect your repository. Render will automatically detect [`render.yaml`](render.yaml) or you can configure manually:
   - **Environment**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `uvicorn api.main:app --host 0.0.0.0 --port $PORT`
4. In the **Environment Variables** section, add:
   - `GROQ_API_KEY`: Your Groq API key from [console.groq.com/keys](https://console.groq.com/keys)
5. Click **Create Web Service**. Once deployed, copy your backend URL (e.g., `https://codebuddy-backend.onrender.com`).

---

### Step 2: Deploy Next.js to Vercel

#### Via the Vercel Web Dashboard (Easiest):
1. Go to [Vercel Dashboard](https://vercel.com/new) and click **Add New...** → **Project**.
2. Select your GitHub repository (`CodeBuddy`).
3. In the **Configure Project** screen:
   - **Framework Preset**: Next.js (automatically detected)
   - **Root Directory**: Click **Edit** and select `frontend` (⚠️ **crucial step**).
4. Expand **Environment Variables** and add:
   ```env
   NEXT_PUBLIC_API_URL = https://codebuddy-backend.onrender.com
   ```
   *(Replace with your actual backend URL from Step 1)*
5. Click **Deploy**.

#### Via the Vercel CLI:
```bash
# Install Vercel CLI if you haven't already
npm install -g vercel

# Navigate to the frontend directory
cd frontend

# Deploy to Vercel
vercel

# Follow prompts:
# - Link to existing project? No
# - Project name? codebuddy
# - In which directory is your code located? ./
# - Want to modify build settings? No
```

Once deployment completes, set your production environment variable:
```bash
vercel env add NEXT_PUBLIC_API_URL production
# Enter your backend URL when prompted: https://codebuddy-backend.onrender.com

# Re-deploy to apply the environment variable
vercel --prod
```

## 🌐 Option 2: Full-Stack Vercel Monorepo (Next.js + Python Serverless)

If you want to host both the Next.js frontend and the FastAPI backend within Vercel as a single project:

1. CodeBuddy includes [`api/index.py`](api/index.py) which exports the FastAPI `app` for Vercel's Python Serverless Function runtime.
2. Import the repository root (`.`) in Vercel:
   - **Root Directory**: `.`
   - In **Environment Variables**, add:
     - `GROQ_API_KEY`: `your_groq_api_key`
3. Click **Deploy**.

> [!WARNING]
> **Serverless Function Limitations:**
> - **Execution Timeout**: Vercel Hobby plan functions time out after 10–60 seconds. Complex agent workflows requiring multiple LLM reasoning cycles may hit this limit.
> - **Ephemeral Storage**: Vercel Serverless Functions only have temporary writable disk in `/tmp`. Files generated by the agent will not persist across separate cold starts.
> - For production workflows, **Option 1** is strongly recommended.

## 📋 Environment Variables Summary

### Vercel (Frontend Project)
| Variable | Required | Description | Example |
| :--- | :---: | :--- | :--- |
| `NEXT_PUBLIC_API_URL` | **Yes** | Public URL of the FastAPI backend | `https://codebuddy-backend.onrender.com` |

### Backend (Render / Railway / Serverless)
| Variable | Required | Description | Example |
| :--- | :---: | :--- | :--- |
| `GROQ_API_KEY` | **Yes** | Groq Cloud API key | `gsk_...` |
| `ALLOWED_ORIGINS` | No | Comma-separated CORS origins (default `*`) | `https://your-frontend.vercel.app` |
| `PROJECT_ROOT` | No | Custom folder for generated code | `/tmp/generated_project` |

## 🔍 Verification Checklist

After deploying to Vercel:
- [ ] Open your deployed Vercel URL.
- [ ] Verify the header shows **FastAPI: Online** with a green pulse dot.
- [ ] Verify **Groq: Connected** is displayed.
- [ ] Run a test prompt: *"Create a single-page stopwatch with start, stop, and lap records using HTML/JS."*
- [ ] Verify the agent streams logs through Planner ➔ Architect ➔ Coder.
- [ ] Inspect the generated code in the file viewer and download the ZIP archive.
